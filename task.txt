# MedWaste
**Система учёта и контроля медицинских отходов класса «Г»**

## 1. Описание кейса

**Контекст**
Медицинские отходы класса «Г» — это токсикологически опасные отходы: просроченные лекарственные препараты, дезинфицирующие средства, ртутьсодержащие приборы, цитостатики. Их обращение строго регламентировано СанПиН 2.1.3684-21 и требует документального сопровождения на каждом этапе — от момента образования в медицинском учреждении до утилизации на специализированном предприятии.

На практике большинство небольших клиник, лабораторий и аптек ведут учёт вручную — в бумажных журналах или Excel. Это приводит к нарушениям: потере документов, невозможности отследить цепочку ответственности, задержкам при проверках агентства по контролю за отходами.

**Проблема**
*   Нет единой цифровой системы учёта движения отходов класса «Г»
*   Передача отходов транспортировщику происходит без надёжной верификации — кто забрал, когда, в каком количестве
*   Документы на каждую партию формируются вручную и легко теряются
*   Переработчик не подтверждает приём в реальном времени — образователь не знает о финальной судьбе партии
*   Контролирующие органы не имеют возможности запросить актуальный цифровой журнал

**Цель проекта**
Разработать платформу (веб-интерфейс/мобильный агент/бот-интерфейс), которая обеспечивает сквозной контроль цепочки обращения медицинских отходов класса «Г»: от момента регистрации партии образователем до подтверждения утилизации. Ключевая механика — автоматизация процесса переработки отходов через маркировку партий отходов.

## 2. Акторы
В системе 5 ролей.

| Актор | Описание | Ключевые действия |
| :--- | :--- | :--- |
| **Образователь** | Медицинская организация (клиника, лаборатория, аптека), которая формирует партии отходов | Создание партий, генерация QR-кодов, выбор организации-переработчика и её водителя, настройка времени доступа, создание и просмотр статуса партии |
| **Водитель** | Перевозчик, который забирает отходы от образователя и доставляет на пункт утилизации. Состоит в одной организации с переработчиком. | Сканирование QR-кода, просмотр данных партии (в рамках временного доступа), отметка о доставке. Данная роль имеет доступ к системе только через QR код партии |
| **Переработчик** | Специализированное предприятие — конечный получатель отходов | Создание карточки водителя, закрытие цепочки учёта (приемка) |
| **Администратор** | Оператор платформы | Управление аккаунтами организаций и ролями, настройка справочников (типы отходов) |
| **Инспектор** | Представитель контролирующего органа (Агентство по контролю за отходами) | Просмотр журналов движения отходов в режиме чтения, выгрузка отчётов за период |

## 3. Особенности и ограничения объектов

**Партия отходов (основная сущность)**
*   Уникальный идентификатор (генерируется системой)
*   Тип отходов класса «Г» (из справочника): лекарственные препараты / дезинфектанты / ртутьсодержащие / цитостатики / иное
*   Количество и единица измерения (кг, л, шт.)
*   Образователь (ссылка на организацию, которая создает партию)
*   Точка вывоза (адрес или геометка)
*   Точка доставки — адрес организации-переработчика
*   Статусная цепочка: создана → в пути → принята переработчиком *(рукописная пометка: утилизация)*
*   Дата и время каждого перехода статуса

**QR-токен**
*   Привязан к конкретной партии
*   Время жизни задаётся образователем (максимально - 7 суток)
*   Содержит информацию об ID партии
*   После истечения доступ к данным партии через этот токен блокируется
*   Один токен — одна партия

**Пользователь / организация**
*   Для всех пользователей: ФИО, Роль, организация
*   Организация: ИНН, КПП, название
*   Для водителей: номер транспортного средства
*   Для образователей: номер лицензии на обращение с отходами, адрес вывоза
*   Для переработчиков: номер лицензии на переработку, адрес площадки, список водителей

**Журнал событий**
*   Каждое действие в системе записывается: кто, что, когда, с каким объектом
*   Является основой для отчётности

**Ограничения доступа**
Каждый актор видит только то ограниченную информацию:
*   Образователь видит только свои партии своей организации
*   Водитель видит только партию, закрепленную за QR кодом доступа
*   Переработчик видит только партии, адресованные его организации
*   Инспектор видит все записи организаций (только на чтение)
*   Администратор имеет полный доступ к объектам системы

## 4. Функциональность

### 4.1. Обязательная (Must Have)

**Управление партиями:**
*   Создание партии с указанием типа отходов, количества, точки вывоза и переработчика
*   Генерация QR-кода (уникального идентификатора) с настраиваемым временем действия (устанавливается образователем)
*   Просмотр текущего статуса всех партий своей организации

**QR-доступ для водителя:**
*   Сканирование QR-кода через мобильное устройство, бот или текстовую альтернативу
*   После успешного сканирования водитель видит: тип и количество отходов, адрес вывоза и доставки, срок окончания доступа
*   Возможность подтвердить передачу
*   Доступ автоматически прекращается по истечении срока токена

**Подтверждение переработчиком:**
*   Переработчик видит список партий, адресованных его организации
*   Подтверждение приёма партии — финальная смена статуса («принята переработчиком»)

**Отчётность:**
*   Экспорт журнала за период в формате Excel/CSV (для образователя и инспектора)

**Доступ и безопасность:**
*   Аутентификация всех пользователей платформы
*   Доступ только к записям своей организации (роли образователь, переработчик, водитель)
*   Доступ ко всем записям системы (роли администратор, инспектор)

### 4.2. Дополнительная (Nice to Have)
*   Дашборд для образователя: статистика по типам отходов за период
*   Пролонгация уже выпущенного QR-токена (продление срока действия)
*   Лог заблокированных попыток (отдельная страница «кто пытался войти по истёкшему токену»)
*   Чат между образователем и водителем.
